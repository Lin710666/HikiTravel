# 量化指标

> 用于答辩演示与文档中说明成果。区分「可实测」与「预期（需上线验证）」，
> 请如实标注，避免夸大。

## 一、可实测的性能指标

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 整单生成耗时（3 天行程，本地 7B/CPU） | 实测约 80 秒 | 后端按 Skill 计时：检索 0.4~7s、规划 15~21s、体检 48~55s |
| 规划耗时（已优化） | 实测 15~21 秒 | 大模型只输出"去哪些景点"的扁平清单，分天/排线交给代码 |
| 回退优化 | 单段 ≤ 25 公里、当天 ≤ 40 公里由代码判定，秒级 | 路线体检与最近邻重排均为纯计算 |
| 天气/POI 数据获取 | 依赖高德 API，命中缓存后 < 1 秒 | 接口耗时（进程内缓存，省掉重复调用与限流等待） |
| 生成中可打断 | 支持取消 / 重试 / 连接自检 | 前端 AbortController + /api/health |
| 前端首屏渲染 | < 3 秒 | 打包后静态资源体积 |

## 二、可用演示呈现的指标

| 指标 | 数值 | 说明 |
|------|------|------|
| 必填字段 | 5 项 | 目的地 / 天数 / 同行人数 / 兴趣导向 / 总预算；缺哪项就明确提示补哪项，不用静默默认值 |
| 异常拦截覆盖场景 | 6 类 | 预算偏低 / 老人×特种兵 / 老人×爬山 / 儿童×特种兵 / 高龄×极低预算 / 必去景点过多 |
| 规划体检维度 | 6 类 | 路径折返 / 跨城点位 / 重复安排 / 必去漏排 / 时间重叠 / 预算漏项 |
| 路线优化 | 确定性 | 按真实坐标算每天总距离、折返、超长单段；最近邻重排当天景点（秒级，可复现） |
| 体检后重生成 | ≤ 1 次 | 仅"硬伤"未解决时触发，带体检结论重排；新版更差则保留原版 |
| 推荐排序综合分 | 3 套 | 景点＝距上一景点×权重＋热度×权重＋评分×权重；餐厅＝距前后景点×权重＋评分×权重；酒店＝评分×权重＋离当天/次日活动区距离×权重 |
| 作息规则 | 3 条 | 非特种兵不早于 8:00 出发；午餐不晚于 14:00；晚餐不早于 17:30（超时优先砍景点，不砍晚餐） |
| 预算口径透明 | 2 条 | 往返大交通为估算值（实际购票为准）；门票价缺失时明确说明按 0 元计 |
| 跳转降级层级 | 4 级 | Scheme → 超时检测 → H5 → 复制口令 |
| 雨天备选（Plan B） | 自动替换室内 | 基于实时天气触发 |

## 四、演示建议

在演示视频/现场，用同一句话对比：
「带 80 岁老人特种兵游杭州，3 天，预算 2000」

展示：① 结构化画像抽取 → ② 系统**建议**调整节奏（用户可选择采纳/保持原样）→ ③ 实时天气 + 时间轴 + 地图轨迹 → ④ 规划体检问题清单 → ⑤ 点击 POI 一键跳转导航/点评/预订（含降级演示）。
